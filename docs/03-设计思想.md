# 03 · 设计思想

> 六条设计原则、为什么可信、不幻觉是怎么做到的、fail-closed 落在哪、有意不做的事。

---

## 一、一句话立场

**一个能拿去做关键决策的内核，第一要求不是"聪明"，而是"说得清、可复现、错的时候认错"。**

灵脑全部设计围绕这句话展开：把一切能确定的做成确定性检查，把一切不能确定的**显式标出来**，
绝不用"看起来合理"填补空白。

---

## 二、六条设计原则

### 2.1 确定性优先（Determinism first）

同一输入必得同一输出。内核不带随机分支；`SEED` 与 `ALGO_VERSION` 写进每份审计的 `reproducible` 字段，
任何人可据以复跑同一结论。默认搜索、规划、因果、采样路径全部走固定种子。

### 2.2 可审计优先（Auditability first）

每步决策都要能回答"**凭什么**"。产出两层证据：

- **依据链**：推理每一步引用了哪些知识 / 约束 / 经验；
- **七段审计报告**：概要 / 轨迹 / 证据 / 约束 / 𝕌 / **证明证书** / 可复现。

### 2.3 神经符号边界（LLM 只做两端）

| 档位 | 来源 | 会幻觉吗 | 能否作为依据 |
|---|---|---|---|
| `PERCEPTION`（`UNVERIFIED_LLM`） | 免费 LLM 把人话转成结构化目标 | **会**（显式标 `mayHallucinate=true`） | **否**，绝不进入证明链或决策依据 |
| `KERNEL`（`DETERMINISTIC`） | 内核 A\* / 知识库计算 | 不会，可复现 | 是 |
| `PROOF`（`AUDITED`） | 七段审计 + 霍尔证明证书 | 不会，可机器验证 | 是（最高保证） |

`ask` / `audit` / `reason` 的返回值都携带 `grounding` 字段与 `disclaimer`；
LLM 解释文本显式标注"可能幻觉，不计入证明或决策依据"。**这条边界由自测持续验证。**

### 2.4 fail-closed（该拒就拒，不降级成"看起来通过"）

灵脑的默认失败方向是**拒绝**，而不是"凑一个结果"。已实装的 fail-closed 点：

| 场景 | 行为 |
|---|---|
| 审计账本缺签名密钥且未显式 opt-in | **拒绝启动**（原 fail-open 漏洞已修；`insecureAudit:true` 为开发期逃生口，带可见告警） |
| MCP 内核导出缺失 | **启动即抛** `MCP_EXPORT_MISSING`（原 try/catch 静默吞已修） |
| 物理载体主版本不符 / 无握手 | **拒绝连接** |
| M2 数值认证预算耗尽（`truncated`） | 一律降档 `truncated-unverified`，**绝不把"未穷尽"说成"已证安全"** |
| 问题不可判定 | 诚实返回 **𝕌**（`reason-unknown :: U=true`），不猜 |

### 2.5 具身无关（Body-agnostic）

大脑不感知具体硬件：物理身体通过**声明式能力契约**接入（能力名 + 类型 + 单位 + 前置条件），
大脑在契约上做 A\* 状态空间规划，执行前过 `check_hard`（SAFE-STOP），执行后 `state_diff` 有界重规划。

### 2.6 诚实降级（Honest degradation）

凡能力有缺口，**在返回值里说**，不在文档里含糊：

- 轻量替代一律标注：符号验证 = 自写约束求解器（**非真实 Z3**）；霍尔证明 = 结构化逐边验证（**非 Coq**）；
  因果发现 = PC-lite 离散近似（**非真实 PC/FCI**）；LSH = SimHash 投影（**非 Milvus**）；
  世界模型 / 反事实 = 线性 SEM + Pearl 三步法（**非 VAE**）。
- 可选依赖缺失时单项降级（不装 `lingshu-solver` 只有 `algebraic_solve` 降级，附明确安装指引）。
- 副作用面审查工具直接报**"完备性不成立"**，不粉饰。

## 三、不幻觉是怎么做到的（三层隔离）

```
自然语言 ──[LLM 感知层]──► 结构化目标 ──[符号内核]──► 决策 + 依据链 + 七段审计
              ▲                              ▲
       标记 UNVERIFIED_LLM            标记 KERNEL / PROOF
       永不进入证明链                  可复现、可举证
```

关键不在"提示词写得好"，而在**结构上让幻觉无处可去**：
LLM 的产物只能变成**结构化目标**（节点、约束、数值），而目标一旦结构化，
后续每一步都由确定性算法执行并留痕 —— 模型没有机会把"编的事实"塞进结论。

## 四、三条分发面必须一致（改内核时的硬约束）

内核以**单一真源**（`灵脑.html`）存在，但对外有三个暴露面，**新增符号必须三面同步**：

| 分发面 | 位置 | 载体 |
|---|---|---|
| 内核自暴露 | `灵脑.html` 的 `globalThis.__WB` | 浏览器 / 内核自检 |
| MCP 自暴露 | `lingnao-mcp.js` 的 `globalThis.__exp` | MCP stdio 工具实现 |
| UMD 白名单 | `build-umd.js` 的 `EXPORT_NAMES` → `lingnao.umd.js` | 浏览器 / Node 库 |

**为什么必须一致**：内核里有、导出里没有，等于这个能力对外不存在（历史上正是这个原因漏过 4 个符号）。
因此 `build-umd.js` 会做重名检查，v1.1.0 起还增加了"三面导出逐名比对"测试。
当前 UMD 导出数 **250**（实测）。

## 五、为什么要有"七段审计"

一段"最优路径 = A→C"的结论，本身无法追责。七段把"凭什么"拆开：

| 段 | 回答的问题 |
|---|---|
| 概要 | 这次决策的输入与结论是什么 |
| 轨迹 | 搜索/推理经过了哪些状态与分支 |
| 证据 | 引用了哪些知识、经验、约束 |
| 约束 | 哪些硬约束被满足，哪些软约束如何权衡 |
| **𝕌** | 哪些部分**不可判定**（认知不确定性 / 偶然不确定性分别量化） |
| **证明证书** | 可机器检验的形式化结论（如霍尔三元组） |
| 可复现 | `ALGO_VERSION` + `SEED` + 时间戳 |

其中"𝕌 段"是设计上最重要的：**允许说"这部分我不知道"**，才谈得上可信。

## 六、安全栈的定位（说清"蛋糕有几层"）

| 层 | 内容 | 性质 |
|---|---|---|
| 形式化证明模块 | M1 门控链（`proveGateChain`）/ M2 数值安全不变式证书（`certifySafetyInvariant`）/ M3 三层裁决表达层（`verdictThreeLayer`）/ M4 完全中介（`proveCompleteMediation`） | M1/M4 = 静态/语法层检查；M2 = 带松弛的数值证书；M3 = **表达层**，不是证明模块 |
| 运行时安全 | CBF-QP 安全滤子、组合 CBF、STL 鲁棒度、Zonotope 可达集、混合自动机 × 自动微分 | 可与证明结论互相印证 |
| 执行闸门 | `execute()` 内 M1 前置守卫 + SAFE-STOP + 审计账本 | 物理动作的唯一受控出口 |
| 会计层 | 最优分配（匈牙利 + LP 对偶证书）、抽象解释（区间格 + widening/narrowing） | 决策与静态分析的量化支持 |

**诚实注**：副作用面审查实测显示，19 个副作用出口中**只有 1 个**（`body-adapter`，物理动作唯一出口）经 M1 门控，
另 18 个（HTTP 外发 1 / Node https 1 / 浏览器 storage 16）在门控作用域之外。
**所以 `proveGateChain` 的结论只对"走 `execute()` 的物理动作"有效。**

## 七、有意不做的事

| 不做 | 原因 |
|---|---|
| **不引入神经网络** | 计算图不可解释、结果不可复现，与"可审计"目标冲突；LLM 只作为**外挂感知层**，不进内核 |
| **不重写求解逻辑** | 代数求解委派给灵数真引擎（区间收缩 + Krawczyk 认证），避免同能力两套实现互相漂移 |
| **不做符号 CAS** | 灵脑要的是"可审计的决策"，不是解析推导；符号能力（`symbolic_verify`）只用于验证路径不变量，且如实标注为 lite 版 |
| **不用"全绿"报结果** | 6 项 KB 能力未接入就如实列出来（v3.1 起的措辞） |
| **不宣称"数学上不可越狱"** | 内核已登记不完备性定理 `THM_GODEL_INCOMPLETENESS`；任何系统同理存在理论边界 |
| **不把托管端点当主营收入形态** | 灵脑的商业模式是商业授权（见 [06 · 商业授权与收费](06-商业授权与收费.md)），不是零售调用 |
