## 一、签署流程

| 步骤 | 动作 | 需要的材料 |
|---|---|---|
| 1 | 双方确认场景、部署方式、实例数、是否需要认证报告 | 使用场景说明、部署拓扑、物理载体/设备清单（具身场景） |
| 2 | 出报价与授权范围，双方确认 | 报价单（按需提供） |
| 3 | 填写本合同（甲方信息由我方补全主体资料） | 乙方营业执照信息、联系人 |
| 4 | 电子签署 | 腾讯电子签（或双方认可的电子签平台）；亦可纸质双签 |
| 5 | 对公转账付款、开具发票 | 付款凭证 |
| 6 | 交付（内核/部署包/认证报告/支持入口）与建联 | 技术联系人 |

**签署方式**：推荐电子签（一式两份、电子签具同等效力）。合同签署地为广州市花都区。

#### 第一条　授权标的

1.1 甲方授权乙方使用「灵脑可审计决策内核」（产品名：`lingnao-mcp`，内核文件 `灵脑.html`，算法版本 `ALGO_VERSION = ____`，包版本 `v____`），以下简称"本软件"。

1.2 本软件功能：在乙方给定的**世界图**与**物理载体能力契约**上，做确定性、可复现的最优决策，
并输出**依据链、七段审计报告与形式化验证结论**（含 `grounding` 分层、不可判定标记 𝕌、M1/M2/M3/M4 模块结论及其边界）。

1.3 本软件以 **MCP（Model Context Protocol）标准接口**（stdio）提供，另有网页形态与 UMD 库形态；
支持**乙方本地嵌入**与**私有化部署**两种方式。

1.4 本软件为**零第三方运行时依赖**的确定性内核，**不含、不调用任何神经网络**；
大模型（若配置）仅用于自然语言感知与结果解释，**不进入决策链与证明链**。

2.3 使用范围：用于乙方内部业务系统 / 自研产品中嵌入调用，用途限于乙方申请的**决策与审计场景**。

2.6 定制内容（勾选适用）：□ 物理载体能力契约定制　□ 安全约束 / SAFE-STOP 规则定制　□ 形式化验证认证报告　□ 设备接入（connector）联调　□ 其他 ________

#### 第五条　验证结论的含义、责任与免责（**核心条款，务必保留**）

5.1 **"可审计 / 已验证"的含义**：本软件输出的"已验证"指——**在给定世界图、能力契约、数学模型与计算预算内，
该决策可复现、依据可举证、形式化结论可机器检验**。**不表示"结果绝对正确"或"绝对安全"。**

5.2 **已知边界的明示**（甲方主动披露，不隐瞒）：
（a）M2 数值安全证书带 `h ≥ −1/B²` **辅助域松弛**，其结论以 `provenBound` 字段为准，**不是无松弛的纯数学证明**；
（b）M1（门控链）与 M4（完全中介）为**静态 / 语法层检查**，M3 为三层裁决**表达层**，不是证明模块；
（c）副作用面完备性**经甲方自查工具检测为"不成立"**：`proveGateChain` 的结论只对走内核 `execute()` 的物理动作有效；
（d）预算内未能穷尽的数值认证一律降档 `truncated-unverified`，**不伪装通过**（fail-closed 设计）；
（e）部分能力为"手写轻量实现"（符号验证、因果发现、世界模型等），已在文档中逐项标注，**非工业级外部求解器**。

5.3 **不保证条款**：甲方**不保证**本软件在所有输入下均产出已验证结论，亦**不保证**输出在任何外部用途下绝对无误。
乙方应将验证结论作为信任参考，**关键决策须结合自身校验与责任设计**。

5.4 **责任上限**：因本软件授权使用产生的甲方累计赔偿责任，以乙方**已支付的当年授权费**为上限；
甲方不对乙方的间接损失、利润损失、数据损失或第三方索赔承担责任。

5.5 **合规边界**：本软件定位为"**软件授权 / 技术服务**"的决策与审计工具，
**不构成**金融投资、医疗诊断、法律、安全认证或任何专业领域的认证结论；
乙方不得将本软件输出用作此类认证依据，亦不得对外宣称获得甲方的"绝对安全"背书。

## 三、关键条款为什么这样写

| 条款 | 设计理由 |
|---|---|
| **5.1 / 5.2 主动披露边界** | 灵脑卖的是"**说得清**"。把 M2 的松弛、M1/M4 的静态性质、副作用面完备性不成立**写进合同**，双方风险都可控；隐瞒才是纠纷来源 |
| **5.3 不保证条款** | 与产品对外口径完全一致（见 [01 · 产品作用](01-产品作用.md) 第六节）。产品自己在 `truncated` 与 6 项未实现能力上就不撒谎，合同也必须一致 |
| **5.4 责任上限 = 当年授权费** | 软件授权类合同的通行做法，让"能赔得起"与"卖得起"同时成立 |
| **5.5 合规边界** | 避免本软件被当作金融/医疗/法律/安全认证结论的依据；也不接受"绝对安全"背书要求 |
| **3.3 无按量计费** | 明确"授权费之外不再按调用收费"，避免同一能力被重复计费 |
| **7.2 数据条款** | 与产品事实一致：本地/私有化完全离线，甲方不接收运行数据；外部模型调用由乙方自行决定 |
| **1.4 无神经网络条款** | 把"内核不引入神经网络"写成合同事实，供乙方合规/审计部门核对 |
| **8.3 终止后删除副本** | 授权是年度的，不是永久买断（旗舰版源码交付按附录单独约定） |

## 四、附件要点（节选）

### 《技术交付附录》

- **嵌入/私有化交付**：约定版本的 `灵脑.html` 内核 + `lingnao-mcp.js` 服务 + 部署说明；
  交付物与 npm 发布版的**一致性核对方式**（比对 `ALGO_VERSION`、工具数、UMD 导出数）。
- **定制能力契约**：乙方物理载体的能力清单（id / 前置条件 / 效果 / 单位），
  及 SAFE-STOP 规则、`check_hard` 判定表、认证报告对象（若含 M2，须写明**域与松弛**）。
- **白标约定**（旗舰版）：允许/不允许的对外呈现方式；不得暗示与甲方存在授权之外的其他关系。
- **版本与更新**：交付版本的升级方式、是否含后续版本（默认仅含交付时点版本 + 约定期限内的缺陷修复）。

### 《SLA 细则》要点

- 缺陷分级（P1/P2/P3）、响应与修复时限、版本通知范围（接口变更 / 审计字段变更 / 数值行为变更）。
- 例外：乙方自有环境（网络、硬件、第三方总线驱动）问题不在甲方责任范围。
- 补偿方式：按档位约定（通常以服务期顺延为主）。
