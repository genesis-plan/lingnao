# 灵脑 LingNao — 第一性原理架构设计

> 本文是 `ARCH-RESTRUCTURE.md`（整理视角）之上的**设计视角**补强：前者回答"怎么组织代码"，本文回答"从第一性原理看，这个产品该长成什么形状、脊柱是什么"。
> 结论先放：**架构脊柱 = 信任防火墙 + 机器可检的证明账本**；数学思想归组是次轴（可发现性），不是脊柱。

---

## 0. 产品的第一性（它到底是个什么）

从记忆与内核逐行取证，灵脑的本质不是"一个大模型"，而是：

**一个可审计的确定性推理引擎 / 认证预言机（CAIS tool-oracle）。**

其全部差异化与时间窗口（30 天现金跑道）里的护城河，浓缩成一句话：

> 别人（概率 LLM）会幻觉、结论不可审计；它**不幻觉、每条结论可追溯到公理**。

这意味着架构的第一性问题不是"算得快不快、模型大不大"，而是：

**能不能让"不幻觉 + 可审计"从注释里的君子协定，变成物理上无法违反的结构铁律。**

---

## 1. 第一性原理推导（5 条）

### P1. 信任边界是架构的脊柱
任何计算只有两类：
- **可能错、但已知其不确定**（PERCEPTION 层：LLM 理解、learned-f、传感器噪声）
- **保证对**（KERNEL / PROOF 层：A\*、值迭代、D-S 包络、区间可达、定理）

这两类必须**物理隔离**——不是字符串标注 `mayHallucinate:true`，而是**模块/类型级隔离**。

当前事实（逐行）：`灵脑.html` 把 `learned-f`（PERCEPTION，可能幻觉）和 A\*（KERNEL，确定性）平铺在同一 `<script>` 作用域，是平等的 JS 函数，靠人工自觉不串味。这是架构债，也是"护城河没落地"的根因。

### P2. 可审计性要求"已证"有唯一真源且机器可检
当前 `MathKernel.theorem` 把 `proof` 当**字符串**登记，不被小内核机检；`CAPABILITY_THEOREMS` 是**手写字符串映射**，无加载期校验。

若"可审计"是可卖点，证明核至少须机检两件事：
1. **推导链闭合**：每条定理的前提解析到公理 / 已证定理（不允许悬空引用）。
2. **能力映射闭合**：每个暴露工具追溯到至少一条定理（不允许"无声明的黑盒能力"）。

否则"可审计"是营销话术。这正是 P3 的真义——一直没兑现。

### P3. 它是引擎不是模型 → 世界图 + 八元组是显式状态机
`WORLD`（全局可变）、`BODY`（全局可变）是隐式依赖，跨函数共享。八元组 𝔹=(X,h,b,f,U,V,Inv,M,B) 应被当作 **typed state 对象**：决策只读它、学习只写候选池。全局可变状态是脆片源（本审计已踩 3 次语法/耦合坑）。

### P4. 面对不可预测真实世界 → 必须有统一的"无知管理层"
我们补的 minimax / 粗糙集 / f-散度 / 可计算性 / 混沌 / 实践理论闭环，本质是同一件事：**知道自己不知道 + 优雅降级**。当前它们各自 `return UNKNOWN`，分散在十几个原语里。

第一性结论：应归到一个 **epistemic-safety（认知安全）层**，每个对外决策都过它，而不是各原语各自为政。

### P5. 学习环必须隔离
`learned-f` / `SelfLearn` 是唯一概率部分。它只能：
- 产**候选**（带 `nondeterministic` 旗）
- 经 **D-S 包络**进决策
- **永不能**悄悄变成公理

KERNEL 须冻结，仅经审计的定理增量更新。

## 2. 由此推出的架构（主轴 = 认知层级，次轴 = 数学思想）

**控制/学习流**：执行结果 → PERCEPTION → 防火墙(隔离) → 只写候选池，永不触公理

## 3. 架构不变量（硬法，写进内核启动自检）

1. **证书不变量**：外部信任的每条输出都附带证书，经机检推导解析到声明公理。无证不出。
2. **防火墙不变量**：PERCEPTION 层值不得直连 KERNEL/PROOF，除非经 `liftToBelief`（D-S 包络记录不确定性）。类型级拒绝。
3. **冻结不变量**：KERNEL 在运行时冻结；learned-f/SelfLearn 的产出只进候选池，进决策须过 D-S，永不成公理。
4. **诚实不变量**：超出自身工具箱 ⇒ 返回 `UNKNOWN`（指向该数学分支），绝不点估计冒充知识。

## 4. 为何契合"实际情况"（不是空想，是算过账的）

- **护城河 = 可审计**：架构把"可审计"做成结构（机检证明账本 + 防火墙），概率 LLM 结构性抄不了。这是 30 天窗口里唯一算数的差异化。
- **单人非技术创始人**：单文件交付是优点（一个文件可审计、一个产物可发）。所以**方案 = 单文件内逻辑分层 + 机检证明账本**，不是拆多文件（B 方案是工程债清理，发布前或你要时再做）。
- **诚实是品牌**：防火墙让"不幻觉"从话术变物理事实，对外可现场演示——契合用户"反过度营销"的硬约束。
- **分发 = MCP 面向 Agent 免费**：接口层薄而稳，防火墙保证 Agent 拿到的每个能力都带证书，可放心分发。

## 5. 我的独立判断（敢泼冷水）

我上一份 `ARCH-RESTRUCTURE.md` 把"按数学思想归组"当主轴——那是*可发现性*维度，对；但**架构脊柱是信任防火墙 + 机检证明账本，不是归组**。归组是整理，防火墙 + 账本是护城河。优先做后者（P3 真义）。

拆多文件（B 方案）是工程债清理，当下 ROI 不如把证明账本机检化。噪声文件清理（C 方案）可顺手做，不阻塞主轴。
