# 02 · 使用指南

> 三种接入形态的上手步骤、MCP 配置、环境变量、物理接入模块用法、自测与常见问题。

## 一、30 秒上手

### ① 克隆即跑（零依赖，不用装任何东西）

```bash
git clone https://github.com/genesis-plan/lingnao && cd lingnao
node lingnao-mcp.js --selftest      # 零依赖内核自检
```

`--selftest` 直接调内核函数（绕开传输层），**通过即说明内核本机可用**。
装 `lingshu-solver` 后 `algebraic_solve` 会走真引擎；不装则该项诚实降级（见第六节）。

### ② MCP 接入（推荐，给 AI 客户端用）

任意支持 MCP 的客户端（Claude Desktop / Cursor / Cline 等）复制 [`mcp.example.json`](../mcp.example.json) 即可，
**不用开网页、不用服务器、不用本地装包**：

```json
{
  "mcpServers": {
    "lingnao": {
      "command": "npx",
      "args": ["github:genesis-plan/lingnao"],
      "env": { "OPENROUTER_API_KEY": "填你的免费Key（可留空）" }
    }
  }
}
```

也可以走 npm 稳定版（[`mcp.json`](../mcp.json) 同款配置）：

```json
{ "mcpServers": { "lingnao": { "command": "npx", "args": ["-y", "lingnao-mcp"] } } }
```

服务端为标准 **MCP stdio**（手写 JSON-RPC 2.0 分帧，零依赖），协议版本 `2024-11-05`，
`serverInfo = { name: "lingnao", version: "1.1.1" }`。

### ③ 网页 / 库形态（零安装）

| 形态 | 用法 |
|---|---|
| 网页演示 | 双击 [`playground.html`](../playground.html)：规划路径 + 七段审计 + 不幻觉分层，**离线可用** |
| 控制台 | 双击 [`lingnao-console.html`](../lingnao-console.html)：三步接入「身体 / 大模型 / 大脑」后「开始干活」 |
| 浏览器库 | `<script src="https://cdn.jsdelivr.net/gh/genesis-plan/lingnao/lingnao.umd.js"></script>` 后用 `window.LingNao` |
| Node 库 | `const K = require('./lingnao-mcp')` —— 直接调内核，**不自启服务** |

## 二、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `LINGNAO_HTML` | 同目录 `灵脑.html` | 指定内核文件路径（旧名 `LINGJING_HTML` 仍兼容）。**部署时 `lingnao-mcp.js` 与 `灵脑.html` 必须同目录**，或用它显式指定 |
| `OPENROUTER_API_KEY` | 无 | OpenRouter 免费 Key，供 `perceive`（NL→JSON）用。**留空可完整运行**，仅感知层降级为结构化输入 |
| `LINGNAO_AUDIT_KEY` | 无 | 审计账本签名密钥（**部署密钥**）。**缺失且未显式 opt-in 时 fail-closed 拒启** |
| `LINGNAO_MEMORY` | `.lingnao-memory.json` | 构建/运行期记忆存档路径（旧名 `LINGJING_MEMORY` 兼容） |
| `LINGSHU_SOLVER_CORE` | 自动寻路 | 显式指定灵数内核文件（开发期本地覆盖用） |
| `BRIDGE_PORT` | `8799` | 身体桥监听端口（`module/lingnao-body-bridge-node.js`） |
| `BODY_PORT` | `8787` | 仿真身体服务端端口（`module/lingnao-body-sim-server.js`） |

### 2.1 审计账本密钥是 fail-closed 的

```bash
# 生产：注入密钥后正常启动
LINGNAO_AUDIT_KEY=<你的部署密钥> node lingnao-mcp.js

# 开发：缺密钥会拒启；确需临时跑，显式认领不安全模式（会打印可见告警，非静默）
# 调用侧传 insecureAudit: true
```

自测输出首行即：
`[AUDIT-LEDGER] WARNING: 未注入签名密钥，已按 insecureAudit:true 以每启动随机密钥启动（开发期不安全模式）。本进程控制者可伪造账本条目。生产部署前必须注入部署密钥。`

## 三、把它当机器人大脑（最小调用序列）

```
1. world_info()                  → 了解场景节点
2. set_world(我的场景)            → （可选）换成你的物理载体/任务图
3. carrier_report(电量,目标,密度)  → 载体上报，拿硬/软约束
4. reason(起点,目标,硬,软)         → 可审计最优路径
5. 载体按 path 执行
6. learn(执行路径, 成功?)          → 置信度更新，越用越准
```

**具身 / 真机器人链路**为四层：
`灵脑大脑(软件) → 身体适配器(软件) → 现场总线(CAN/RS-485/EtherCAT) → 传感器·执行器(物理)`。
大脑比对主版本，**不符或无握手将拒绝连接（fail-closed）**。

具身调用序：`attach_body` → `plan_task` → `check_hard`（不可逆动作前 SAFE-STOP）→ `execute_task` → `state_diff` → 有界重规划（`maxReplans`）。

### 3.1 端到端试通（无硬件）

```bash
node module/lingnao-body-sim-server.js         # 起一个仿真 AGV（默认 :8787）
# 再打开 lingnao-console.html，「真实身体(WebSocket)」填 ws://localhost:8787
# 需要真连工业协议时（浏览器连不了串口/Modbus），再起本地 Node 驱动桥：
node module/lingnao-body-bridge-node.js        # 默认 :8799，BRIDGE_PORT 可改
```

## 四、物理接入模块（连接真实机器 / 设备）

把任意机器/设备用「**标准语义优先 + 拓扑结构识别 + 最小锚定兜底**」接进灵脑，产出一层**翻译壳（canonical adapter）** ——
灵脑只懂规范语义，对方内部实现**不碰、不复制**。

> **关键点：今天就能用，不需要任何硬件。** 没硬件能跑的是**软件路径**（识别 / 标准导入 / 字节解码）；
> 只有「真连活设备」才需要硬件驱动。

### 4.1 无硬件可跑的三条软件路径

| 路径 | 函数 | 你给什么 | 它返回什么 |
|---|---|---|---|
| ① 拓扑识别 | `classify(观测)` | 变量名列表 + 动作名列表 | 设备类 `id`/置信度，或 `needsAnchor` |
| ② 标准导入 | `importStandard(kind, data)` | 厂家标准文件（点表 / 簇列表 / AAS…） | 变量名 → 规范槽的 `nameMap` |
| ③ 字节解码 | `decode.*` | 原始协议帧字节 | 可读状态对象 |

```bash
cd module && node demo-access.js       # 看三条路径的实际输出
```

```js
const A = require('./module/lingnao-access.js');

// ① 识别电机
A.classify({ protocol:'profidrive',
  variables:{speed:'number',torque:'number',current:'number',temperature:'number'},
  actions:['start','stop','set_speed'] });
// → { matched:true, best:{id:'drive.motor'}, confidence:0.7, ... }

// ② 导入 Modbus 点表
A.importStandard('point-table', { '40001':{slot:'speed'}, '00001':{slot:'run'} });
// → { nameMap:{ '40001':'speed', '00001':'run' }, ... }

// ③ 解码 CiA402 状态字
A.decode.cia402Status(0x0007);
// → { bits:{...}, state:'switched_on', ... }
```

### 4.2 真实驱动（需硬件）：connector 契约

软件路径只解决"语义识别 / 映射 / 解码"。要**真连活设备读写**，需要硬件拥有者提供一个 **connector**，实现三件事：

```js
// 照抄 module/connector-template.js 的 MyConnector
detect(url) → { protocol, host, port, mediumHint }                            // 从地址识别协议
ingest(link, opts) → { variables:{name:type}, actions:[], sample, client? }    // 读硬件→观测
send(cmd)  → Promise<{ok}>                                                    // (可选) 规范命令→写回硬件
```

- 字节解析**直接用本模块已实装的 `decode.*`**，不用自己写协议解析；
- 识别 / 映射 / 翻译壳由 `classify` / `importStandard` / `connect()` 自动完成；
- 跑通演示：`cd module && node connector-template.js`（软件内，无硬件，只验证接线形状）。

**诚实边界**：上面骨架**未连真机验证**（开发机无硬件）。按自己硬件把 `ingest` 的样例数据换成真实读数即可接真机。

### 4.3 诚实边界（务必读）

- **能接 = 设备暴露标准协议 / 接口**；黑盒私有、无文档、加密无凭证 → 走 `needsAnchor`（人锚 1 个语义槽，或导入厂家标准文件），**绝不硬套、不复制对方系统**。
- **`connectorStatus()` 如实标驱动状态**：`supported:true` 仅 `ws` / `modbus-tcp` / `mqtt`；
  其余 `supported:false` 表示**仅建档、需硬件**，本机只提供字节解码自测 + 标准导入，**不谎称能连真机**。
- 输出是**翻译壳**，不是对方系统的克隆。
- 安全敏感执行面（如 `consumer.lock` / 电机启停）的控制指令**必须经内核 HITL / SAFE-STOP / 审计账本 fail-closed**，不可绕过。

已落地清单见 [04 · 技术参考](04-技术参考.md) 第三节与 [11 · 机器与协议目录](11-机器与协议目录.md)。

## 六、常见问题

**Q：不装 `lingshu-solver` 会怎样？**
只有 `algebraic_solve` 一项降级（返回 `available:false` + 明确的安装指引），其余 61 项能力照常。
装上后走灵数真引擎（区间收缩 + Krawczyk 认证），自测输出会显示 `engine=lingshu-solver (灵数求解器)`。

**Q：留空 `OPENROUTER_API_KEY` 会怎样？**
大脑以**结构化输入**运行，100% 确定性与全部规划/审计能力仍可用；只是不能用自然语言直接说目标。

**Q：为什么缺审计密钥就拒启？**
审计账本若用每启动随机密钥，本进程控制者就能伪造条目 —— 那等于账本无效。
所以**默认 fail-closed**，只有显式传 `insecureAudit:true` 才以可见告警的降级模式启动（开发期逃生口）。

**Q：`--selftest` 为什么不说"全部通过"？**
因为 6 项 KB 相关能力**确实没接入**。用"全部通过"会暗示产品能力完整，这是**假绿**。
现在的措辞是「核心 52 项工具验证通过」+「已知未实现能力 6 项」。详见 [08 · 版本管理](08-版本管理.md)。

**Q：我能拿它当"绝对安全"的证明吗？**
不能，也不这么宣称。M2 证书带 `h ≥ −1/B²` 辅助域松弛；M1/M4 是静态/语法层检查；
副作用面完备性**当前不成立**。我们提供的是"**可验证的部分盖章 + 不可验证的明说**"。

**Q：网页端会上传我的数据吗？**
`playground.html` / `lingnao-console.html` 是纯本地页面，内核在浏览器内运行；
只有你主动填了 Key 并使用感知功能时才会请求 OpenRouter。
