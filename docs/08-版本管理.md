# 08 · 版本管理

## 一、两套版本号（别混用）

灵脑同时存在**两个版本号**，各自负责不同的事：

| 版本 | 载体 | 当前值 | 含义 |
|---|---|---|---|
| **内核算法版本** `ALGO_VERSION` | `灵脑.html` | `3.1` | 决定**可复现信息**：审计报告里 `reproducible.algorithmVersion` 记录它。算法行为一变就必须升 |
| **MCP 包版本** | `package.json` / `glama.json` / `serverInfo.version` / npm | `1.1.1` | 决定**分发与依赖**：npm 安装、市场登记、客户端拉取 |

**规则：内核算法变了 → `ALGO_VERSION` 必升；对外接口或分发内容变了 → 包版本必升。**
两者独立演进：`v3.1` 内核可以对应 `1.1.0` / `1.1.1` 等多个包版本。

## 二、发布前一致性清单（逐项核对，缺一不可）

| # | 核对项 | 判定方式 |
|---|---|---|
| 1 | `package.json` version == `glama.json` version == `serverInfo.version` == npm `latest` | 四处字符串逐一比对 |
| 2 | `ALGO_VERSION` 是否本次该升 | 若算法/数值行为变更则为**必须** |
| 3 | **三面导出逐名比对**（内核 `globalThis.__WB` / MCP `globalThis.__exp` / UMD `EXPORT_NAMES`） | 当前 **250 / 250 / 通过 24 失败 0** |

| 5 | 工具数各处声明一致 | `TOOLS.length` == `glama.json` == `smithery.yaml` == `llms.txt` == `openai-tools.json` == `anthropic-tools.json` |
| 6 | `--selftest` | 打印"核心 N 项通过" + "已知未实现 M 项"，exit 0，**无 FAIL** |

| 8 | 文档数字同步 | README / docs 里出现的版本、导出数、工具数、测试数全部核对 |
| 9 | 许可与登记字段 | `license` 字段、README 许可段、LICENSE 三者一致 |

### 2.1 两个已知的发布坑（都踩过）

**坑一：npm 发布后约 30 分钟才可见。**
`npm publish` 打印成功且退出码 0，但 registry 约 **30 分钟**后才可见；
期间的中间态**全都像失败**（单版本端点 404、`latest` 仍是旧版、tarball 404、重复发布报 409）。
**判定失败的门槛是"≥30 分钟后复查"，最终以 tarball 的 shasum 与发布票根一致为铁证。**
⇒ **别过早改版本号**（会让仓库与 registry 永久错位），**更别把中间态当失败对外宣告**。

**坑二：`files[]` 内的文件一改，仓库就与已发布包漂移。**
`package.json` 的 `files[]`（`lingnao-mcp.js` / `lingshu-bridge.js` / `灵脑.html` / `lingnao.umd.js` / `ima_*.json` / `llms.txt` / `openai-tools.json` / `anthropic-tools.json` / `README.md` / `LICENSE`）
是**已发布 tarball 的内容清单**。改动其中**代码文件**后若不发版，会出现"clone 得到的 ≠ npm 装到的"。
⇒ 规则：**文档性改动可随下次发版带上；代码改动必须与版本号一起走。**

## 三、兼容性承诺

| 对象 | 承诺 |
|---|---|
| **工具名** | **只增不改**。改名 / 删除视为破坏性变更，必升 minor，并在发布说明中列明迁移方式 |
| **工具返回值** | **只增字段不删字段**；新增字段一律可选，老调用方不需改动 |
| **审计报告结构** | 七段结构（概要/轨迹/证据/约束/𝕌/证明证书/可复现）稳定；新增内容追加在末尾 |
| **`grounding` 分层** | `PERCEPTION` / `KERNEL` / `PROOF` 三档语义不变（这是不幻觉承诺的技术基础） |
| **fail-closed 行为** | 只可加强不可放松；放松须在发布说明中明示并给出理由 |
| **许可** | 变更不溯及既往；历史版本按其发布时的许可提供 |

## 五、回滚与追溯

- 内核算法的可复现性由 `ALGO_VERSION` + `SEED` + 时间戳保证：**同一版本必得同一结论**。
- 已发布 npm 版本**不删除**（tarball 长期可溯）；出错版本用**新版本修复**，不覆盖旧版本。
- 关键行为变更（门控 / 审计 / 许可 / 工具名）须在发布说明中列明，并在本文件第四节留下记录。
