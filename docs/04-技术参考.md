## 二、单一真源与三面导出

| 分发面 | 位置 | 用途 |
|---|---|---|
| 内核自暴露 | `灵脑.html` 的 `globalThis.__WB` | 浏览器直开 / 内核自检 |
| MCP 自暴露 | `lingnao-mcp.js` 的 `globalThis.__exp` | MCP stdio 工具实现 |
| UMD 白名单 | `build-umd.js` 的 `EXPORT_NAMES` → `lingnao.umd.js` | 浏览器 `<script>` / Node `require` |

**改内核时的硬约束**：新增符号必须**三面同步**。内核里有而 UMD 白名单没有 = 该能力对外不存在
（历史上正是此因漏过 4 个符号，v1.1.0 修复）。构建脚本会做重名检查并打印导出数。

```bash
node build-umd.js
# → OK 生成 lingnao.umd.js  bytes=574968  chars=459766  导出=250
```

## 五、形式化证明模块 M1–M4（摘要）

> 完整规格见 [10 · 形式化证明规格](10-形式化证明规格.md)。

| 模块 | 工具 | 证什么 | 性质 |
|---|---|---|---|
| **M1** | `prove_gate_chain` | 门控逻辑**对不对**（soundness）：把 `execute()` 里的隐式守卫提升为显式门控规格表并静态证明 | 静态检查（零副作用） |
| **M2** | `certify_safety_invariant` | 不等式安全不变式：`∀x∈域 h(x)≥0` ↔ 违反系统无实数解，**委派灵数**出真数学证明 | 数值证书，**带 `h ≥ −1/B²` 辅助域松弛**，强制标注 `provenBound` |
| **M3** | `verdict_three_layer` | 把"计算超时"与"逻辑不可判定"分开裁决（refuse / degrade-conservative / record-capability-limit） | **三层裁决表达层**，不是证明模块 |
| **M4** | `prove_complete_mediation` | 是否所有副作用出口**都过闸**（completeness，M1 的补集） | 参考监视器三性质（Mediation / Separation / Recency）+ 正则闭合逃逸（`Function()` / `setTimeout('字符串')` / `with`），12 变异测试全抓 |

**M2 的诚实语义**：预算耗尽（`truncated`）一律降档 `truncated-unverified`，**绝不把"未穷尽"说成"已证安全"**。

## 六、副作用面审查（诊断工具）

```bash
node module/lingnao-sideeffect-audit.js
```

实测输出（2026-09 复核）：

| 类别 | 出口数 | 受控情况 |
|---|---|---|
| `body-adapter`（物理动作唯一出口） | 1 | ✅ 在 M1 门控**之后** |
| `http-fetch`（浏览器外发） | 1 | 🔴 execute 之外 |
| `node-https`（Node 外发） | 1 | 🔴 execute 之外 |
| `storage`（localStorage / sessionStorage / IndexedDB） | 16 | 🔴 execute 之外 |
| `node-net` / `eval` | 0 / 0 | — |

**结论：受控 1 处、未受控 18 处，"完备性不成立"。**
意味着 `proveGateChain` 的结论**只对走 `execute()` 的物理动作有效**。
审计事件种类数 = 9（`AUTHZ` / `complete-mediation-proof` / `execute-*` / `firewall-reject` / `gate-proof*` / `safety-layers-report`）。

> 工具自身声明："正则静态扫描，可能漏报（间接调用/动态分发），不会捏造。本工具给出事实清单，不是数学证明。"
