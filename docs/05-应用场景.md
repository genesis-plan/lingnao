# 05 · 应用场景

> 灵脑真正能落地的场景、每个场景的入口与边界，以及**不适用**的场景。

---

## 一、判断标准：什么时候该用灵脑

用三个问题筛：

1. **这个决策要不要"说得清凭什么"？**（要 → 适合；不要、只要"看起来对" → 直接用大模型更省事）
2. **同一输入能不能接受不同答案？**（不能接受 → 适合；能接受 → 概率模型更便宜）
3. **错了之后有没有人承担后果？**（有 → 适合；没有 → 适合度下降）

三个都"是"，灵脑就是对的工具；有一个"否"，就该考虑别的方案。

---

## 二、场景一：AI Agent 的可审计决策后端

**痛点**：Agent 调大模型做规划，结论无法复现、出错无法追责，且模型会在证据不足时硬编。

**做法**：把灵脑作为 MCP 工具挂到 Agent 后面，让"要不要做这个动作"由确定性内核裁决：

```
Agent（LLM）→ 提出候选目标 ──► 灵脑 reason/audit ──► 可审计路径 + 七段审计 + 𝕌 标注
                    ▲                                     │
                    └────── LLM 只负责把结论讲成人话 ◄────┘
```

**入口**：`{"mcpServers":{"lingnao":{"command":"npx","args":["github:genesis-plan/lingnao"]}}}`

**边界**：灵脑不给世界知识，也不做开放域问答。它只在你给定的世界图上做最优且可审计的决策。

## 三、场景二：机器人与具身智能（灵脑的主战场）

**痛点**：每换一台设备就重写一遍大脑；安全动作没有统一闸门；执行偏差无法闭环。

**做法**：用**声明式能力契约**接入任意身体，全部规划/执行走同一套可审计管线：

```
attach_body（能力契约：id / pre.require / effect.set|inc）
   → plan_task（A* + h_max 可采纳启发式 → 最优动作序列）
   → check_hard（不可逆动作前 SAFE-STOP，命中即拒）
   → execute_task（逐步执行 + 观测偏差 + 有界重规划 maxReplans）
   → state_diff / learn（偏差入库，置信度更新）
```

**典型子场景**

| 子场景 | 用到的能力 |
|---|---|
| AGV / 移动机器人调度 | 硬软约束（电量 <20 禁离充电座）+ A\* 最优路径 + 重规划 |
| 机械臂 / 产线动作编排 | 动作序列规划 + SAFE-STOP + 有界重规划 |
| 多机器人资源分配 | 匈牙利 + LP 对偶证书（`safety_audit` 纵深报告） |
| 协作序列的结构风险 | `van_der_waerden_trap` 检出周期独占与结构退化 |
| 老设备/无精确模型 | `model_free_cbf` 用轨迹学安全屏障 |

**无硬件也能验**：`node module/lingnao-body-sim-server.js` 起仿真 AGV，再用 `lingnao-console.html` 填 `ws://localhost:8787` 端到端试通。

**边界**：真实机器人链路是四层（大脑 → 身体适配器 → 现场总线 → 传感器/执行器），
**大脑只负责决策与审计**；现场总线的真实驱动需要硬件（当前仅 `ws` / `modbus-tcp` / `mqtt` 已实装）。

## 四、场景三：把老设备接进大脑（翻译壳）

**痛点**：工厂里设备协议五花八门（Modbus / OPC-UA / PROFINET / DL645 / Matter…），
每接一台都要人肉理解厂家私有的点位语义；私有黑盒设备更是无从下手。

**做法**：三步软件路径（**无硬件当天可跑**）——

| 步骤 | 你给什么 | 得到什么 |
|---|---|---|
| ① 拓扑识别 `classify` | 变量名 + 动作名 | 设备类（`drive.motor` / `plc` / `meter.electric`…）或 `needsAnchor` |
| ② 标准导入 `importStandard` | Modbus 点表 / OPC-UA Companion / Matter 簇 / AAS… | 变量名 → **规范槽** 映射 |
| ③ 字节解码 `decode.*` | 一帧原始报文 | 可读状态（状态字 / 过程值） |

产出一层**翻译壳**：灵脑只懂规范语义，**不碰、不复制对方内部实现**。

**边界（务必读）**：能接 = 设备暴露标准协议/接口。黑盒私有、无文档、加密无凭证 → 走 `needsAnchor`（人锚一个语义槽），
**绝不硬套**。30 条协议中**只有 3 条**已实装真实驱动，其余为"仅建档、需硬件"，**不谎称能连真机**。

## 五、场景四：合规与审计敏感场景

**痛点**：流程要被审计，但"AI 说了算"不可举证 —— 拿不出"当时凭什么这么决定"。

**做法**：七段审计报告 + 审计账本（SHA-256 哈希链 + HMAC 单写者签名 + 缺密钥 fail-closed 拒启）。

| 需求 | 对应产物 |
|---|---|
| 决策可复现 | `ALGO_VERSION` + `SEED` + 时间戳（七段审计"可复现"段） |
| 决策可举证 | 依据链 + 证据段 + 霍尔证明证书 |
| 动作有闸门 | M1 门控链证明 + SAFE-STOP + 效应闸运行时报告 |
| 账本不可篡改 | 签名审计账本（fail-closed；`insecureAudit:true` 会留可见告警） |
| 不可判定要说清 | 𝕌 段（认知不确定性 / 偶然不确定性分别量化） |

**边界**：M1/M4 是静态/语法层检查，M2 带辅助域松弛，副作用面完备性**当前不成立**（详见 [04 · 技术参考](04-技术参考.md) 第六节）。
**不构成**金融投资、医疗诊断、法律或任何专业领域的认证结论。

## 六、场景五：教学、研究与技术对照

**为什么适合教学**：它把"确定性 vs 概率"的分界线做成了可运行对象。

- `playground.html` 双击即开：**同一个场景**里同时看到规划路径、七段审计、以及"哪一层会幻觉"的分层标注；
- `node lingnao-mcp.js --selftest` 是可跑的教学材料 —— 包括它**如实披露**的 6 项未实现能力；
- `node module/lingnao-sideeffect-audit.js` 演示"完备性审查"如何给出**对自己不利**的结论。

**边界**：灵脑不含世界知识，不能当百科或家教；要开放域语言能力请直接用大模型。

## 七、不适用场景（诚实清单）

| 场景 | 为什么不适合 | 建议替代 |
|---|---|---|
| 开放域问答 / 写作 / 翻译 | 灵脑不生成文本、不含世界知识 | 直接用大模型 |
| 符号微积分 / 解析推导 | 灵脑不做符号 CAS | 专业 CAS |
| "保证找到全部解" | 一般情形不可判定 | 灵数求解器（**尽力穷尽 + 诚实标 `truncated`**） |
| 需要神经网络拟合的大规模任务 | 内核**不引入神经网络**（可审计性优先） | 专用 ML 模型 |
| 需要"绝对安全"背书的对外承诺 | M2 带松弛、副作用面完备性不成立 | 不得如此对外宣称 |
| 无标准协议的黑盒私有设备 | 无从识别，只能人锚 | 需人工提供厂家文档 |

## 八、已跑通的最小端到端（可复现）

```bash
# 1) 内核自检
node lingnao-mcp.js --selftest

# 2) 仿真身体 + 控制台（浏览器打开 lingnao-console.html，填 ws://localhost:8787）
node module/lingnao-body-sim-server.js

# 3) 接入模块三条软件路径
cd module && node demo-access.js

# 4) 副作用面自查（会报"完备性不成立"，这是设计上的诚实）
node module/lingnao-sideeffect-audit.js
```
