# 01 · 产品作用

> 灵脑是什么、解决什么问题、给谁用、能力与边界、对外口径。

---

## 一、一句话

**灵脑 LingNao 是一个本地确定性、可审计的决策内核 —— 不是概率生成式大模型，不幻觉。**

单文件内核 `灵脑.html` 把「世界图 → A\* 可审计推理 → 物理载体执行 → 学习闭环」封装为单一引擎，
对外以 **MCP stdio 服务 / 网页演示 / UMD 库**三种接口暴露。零第三方依赖、零服务器、可离线。

- 仓库：`genesis-plan/lingnao`
- npm：`lingnao-mcp`
- 在线试用：<https://hclj-1409755229.cos.ap-guangzhou.myqcloud.com/lingnao/playground.html>

---

## 二、它解决什么问题

| 痛点 | 灵脑的做法 |
|---|---|
| 大模型决策不可复现、无法追责 | 决策全部走本地符号内核（A\* + 硬/软约束 + RSG 推理状态图）；同样输入必得同样输出 |
| 说不清"这个动作为什么被允许" | 每步给**依据链** + **七段审计报告**（概要/轨迹/证据/约束/𝕌/证明证书/可复现） |
| 不可判定时模型会编一个答案 | **诚实返回 𝕌**（`reason-unknown :: U=true`），绝不猜测；不确定性量化到认知与偶然两类 |
| 换一台机器人就要重写大脑 | **声明式能力契约**：任意物理身体按契约接入，大脑不感知具体硬件 |
| 设备协议千差万别、无从下手 | **物理接入模块**：30 条协议登记 + 17 张规范卡 + 9 类字节解码器，无硬件也能先用软件路径 |
| 大模型输出混进决策链 | **神经符号边界**：LLM 只在感知（NL→JSON）与解释两端，显式标 `mayHallucinate=true`，**绝不进入证明链或决策依据** |

## 三、给谁用

| 对象 | 用法 | 入口 |
|---|---|---|
| **AI Agent 开发者** | 把灵脑当一个标准 MCP 工具挂到 Claude Desktop / Cursor / Cline 等客户端 | `npx -y lingnao-mcp` |
| **机器人 / 具身智能** | 用能力契约接入真实身体，做**可审计**的状态空间规划与执行（含 SAFE-STOP） | `attach_body` → `plan_task` → `execute_task` |
| **合规 / 审计场景** | 需要"决策可复现、可举证、可追溯"的场合 | 七段审计 + 审计账本 |
| **教学 / 研究** | 观察确定性推理与不幻觉分层如何落地 | `playground.html` 双击即开 |
| **工业 / IoT 设备接入** | 用翻译壳把厂家设备接进大脑，不碰对方内部实现 | `module/lingnao-access.js` |

## 四、能做什么（已落，可取证）

- 在任意「世界图」上做**最优且可审计**的决策：A\* 最优路径 + 硬/软约束 + RSG 推理状态图 + 系统 1 高置信快答
- **七段审计报告**与**霍尔证明证书**（`audit-proof` 实测输出 `{S∈W} A* {inv1} {T∈W ∧ 最优cost=1}`）
- **量纲分析**（物理正确性）、**声明式能力契约**、**观测契约可区分性**
- **具身层**：A\* 状态空间规划 + SAFE-STOP + 任意身体能力契约 + 有界重规划
- **安全栈**：CBF-QP 安全滤子 + 组合 CBF + STL 鲁棒度 + Zonotope 可达集 + 混合自动机 × 自动微分
- **最优分配**：匈牙利算法 + LP 对偶证书；**抽象解释**：区间格 + widening/narrowing
- **因果**：do 演算（后门 / 前门准则）+ 线性 SEM 世界模型 + Pearl 反事实三步法
- **知识接入**：第三方 IMA 知识库（431 条公理/定理/定义/方法）载入与检索（仅参考，不进证明链）
- **物理接入模块**：30 条协议登记（`ws` / `modbus-tcp` / `mqtt` 三条已实装真实驱动）、17 张规范卡、9 类字节解码器、13 条标准导入分支 —— **无硬件即可跑**（见 [04 · 技术参考](04-技术参考.md)）
- **MCP 工具 62 个**（实测 `lingnao-mcp.js` 的 `TOOLS` 数组，无重名），另含 6 项 "需接入 KB 才可用" 的能力，如实单列不计入绿色通过

## 五、不做什么（诚实边界）

**能力缺口，逐条明说：**

| 事项 | 实情 |
|---|---|
| 不生成文本、不编造事实 | 推理结果可复现、可审计、不幻觉；语言能力只来自 LLM 感知/解释层，且不进决策链 |
| **不称"数学上不可越狱"** | 内核已登记不完备性定理（`THM_GODEL_INCOMPLETENESS`）；任何系统同理存在理论边界 |
| **轻量替代（手写 lite 版，均非工业级外部求解器）** | 符号验证 = 自写约束求解器（非真实 Z3）；霍尔证明 = 结构化逐边验证（非 Coq 机器证明）；因果发现 = PC-lite 离散近似（非真实 PC/FCI）；LSH = SimHash 投影（非 Milvus）；世界模型/反事实 = 线性 SEM + Pearl 三步法（非 VAE） |
| **M2 安全证书带松弛** | `verified` 实为 `h ≥ −1/B²` 辅助域松弛，规格强制标注 `provenBound`；**不是无松弛的纯数学证明** |
| **M1 / M4 是静态/语法层检查** | M1（门控链）与 M4（完全中介）为证明语言包装的静态检查；M3 是三层裁决**表达层**，不是证明模块 |
| **副作用面完备性不成立** | 副作用审查工具实测：19 个出口中仅 1 个经 M1 门控，18 个在门控作用域之外（HTTP 外发 1 / Node https 1 / 浏览器 storage 16）。`proveGateChain` 的结论**只对走 `execute()` 的物理动作有效** |
| **6 项 KB 能力未接入** | `kb-summary` / `knowledge_query` / `knowledge_add` / `knowledge_ann` / `knowledge_distill` / `cog-graph` 恒返 `available:false`，属**已知未实现能力** |
| **无世界知识、无开放域语言能力** | 离线时感知降级；规划基于有限图 |
| **8 类数学尚未实装** | MPC、SOS/SDP 障碍证书、一般 LP 求解器、一般非线性可达集等 |

> **"全绿"不是我们的措辞。** `--selftest` 现在如实打印「核心 52 项工具验证通过」+「已知未实现能力 6 项」，
> 不再用"全部通过"暗示产品能力完整（此项为 v3.1 的诚实性修复，见 [08 · 版本管理](08-版本管理.md)）。

## 六、对外口径（红线，不可越）

1. **说"可审计、可复现、确定性"，不说"绝对正确"**。
2. **说"已验证的部分盖章 + 不可验证的明说"，不说"保证不漏"**。
3. **LLM 永远标 `UNVERIFIED_LLM` + `mayHallucinate`**，任何场合不得暗示 LLM 输出可进决策依据。
4. **驱动状态如实分档**：`connectorStatus()` 中 `supported:true` 仅 `ws` / `modbus-tcp` / `mqtt`；其余为"仅建档、需硬件"，**不谎称能连真机**。
5. **工具数用实测值**（62），并在含 KB 项时同步标注"需接入 KB"。

## 七、与灵数的关系（两个独立产品，勿混淆）

| 产品 | 是什么 | 仓库 | npm |
|---|---|---|---|
| **灵脑 LingNao**（本仓库） | **大脑**：感知 / 规划 / 审计 / 学习 / 具身裁决 | `genesis-plan/lingnao` | `lingnao-mcp` |
| **灵数 LingShu** | **求解器**：方程组实数解（区间收缩 + Krawczyk 认证） | `genesis-plan/lingshu-solver` | `lingshu-solver` |

灵脑**不重写求解逻辑**：`algebraic_solve` **委派**给灵数真引擎。
灵数是**可选依赖**（`optionalDependencies: lingshu-solver ^1.0.3`）—— 不装它，灵脑其余能力照常运行，仅该项诚实降级。
