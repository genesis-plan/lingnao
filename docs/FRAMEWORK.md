## 五、Layer 3：有限范围安全层（部分验证数学结构的有界利用）


### 核心思想

对于尚未被完全证明但已被数值验证到极高范围的数学猜想，将使用范围明确限定在已验证高度以内，作为灵脑的可选安全判定层。超出验证范围时，系统自动降级为"不可判定"，触发保守策略。

### 当前可用：有限范围黎曼陷阱

**数学状态：** 黎曼猜想未被证明，但已数值验证至虚部高度 **T₀ = 3×10¹²** 的所有零点均位于临界线上。

**陷阱设计：**

```
设设备状态映射到虚部高度 t = E(s)

if t ≤ T₀（3×10¹²）：
    计算谱相干函数 C(0.5, t) = |ζ(0.5 + it)|² / (1 + |ζ(0.5 + it)|²)
    如果 |C(0.5, t) - 0.5| < ε → 状态合法
    否则 → 拒绝

if t > T₀：
    标记为"超出验证范围"
    进入保守模式：默认拒绝，或转交其他判定层
```

**审计标注：** 判定结果标注为 **"Tier 1：数值验证级（T₀=3×10¹²以内）"** ，明确区别于Tier 0数学证明级。

**扩展性：** 这一方法可推广到其他"已被部分验证的猜想结构"，例如：
- **有限范围哥德巴赫猜想**：已验证至极大偶数
- **有限范围素数间隙猜想**：已验证的间隙分布

**对灵脑的价值：** 在有限范围内引入数论结构作为安全判定机制，同时保持诚实——明确标注使用范围和信任等级。

### Layer 3 诚实警示（独立判断，须进文档）

黎曼陷阱作为**字面设计**存在两个必须标注的问题，不应作为真实安全闸：

1. **可计算性**：在 JS / 浏览器内核中计算 `ζ(0.5 + it)` 至 `t = 3×10¹²` 不可行——该高度远超任何前端数值实现的算力（即便服务端也需专用算法与大量算力）。"已验证至 T₀=3×10¹²"是数论界的离线计算结果，不是灵脑能在运行时复算的。
2. **判据数学问题**：`C(0.5,t) = |ζ|²/(1+|ζ|²) ∈ [0,1)`，条件 `|C−0.5|<ε` 等价于 `|ζ(0.5+it)|² ≈ 1`，即 ζ 的模长接近 1。这与"状态是否安全"没有已知的数学联系——它不是一个有意义的物理/安全判据，而是一个**概念示意**。

**建议**：Layer 3 保持为 "Tier 1 研究示意"，明确标注"不可在运行时复算、判据未建立数学意义、禁入证明链"，不要把它写成已可用的安全层。若日后要做"数论结构作为安全判定"的真实研究，需先解决上述两点，而非直接套用本设计。

### Layer 2 / CLF-CBF 实现备注（2026-09-02 下午，给实现者）

- **dual-aware 约定**：内核用显式双数原语（`dAdd`/`dSub`/`dMul`/`dPow`/`dual`，**无运算符重载**）。`h`/`V` 必须以这些原语书写（如 `h = x => L.dSub(L.dual(1,0), x[0])`），否则喂入 `clfCbfUnified` 的对偶求导链会得 `NaN` → 误判可行/不可行。**`f`/`g` 返回普通数组/矩阵**（`g` 朝向为 inputs×states，与 `cbfCompose` 一致）。`linearControlSpec(A,B,P,cList,dList)` 已把矩阵规范转为 dual-aware 的 `h`/`V`，是 MCP/测试以矩阵构造系统的入口。
- **诚实边界已落实**：CLF 与 CBF 约束冲突时 `clfCbfUnified` 返回 `feasible:false`（绝不谎称安全）；前提不足的陷阱返回 `verdict:'undecided'`（标 𝕌），不猜测。
- **验证**：`test/test-safety-traps-clfcbf.js` 覆盖六陷阱 + CLF-CBF 平凡/修正/冲突/聚合 + `linearControlSpec` 集成，28/0 通过；`lingnao-mcp.js` 已暴露 8 个对应 MCP 工具（`tools/list` 共 54 个）。
